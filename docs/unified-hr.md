# 秋奈 × 深夜員工 HR

員工入口為 `https://hr.wearestilllhere.com`，主管入口為 `https://eip.wearestilllhere.com`。

員工頁面依已驗證的 Discord 身分讀取在職部門，沒有部門切換模式。姓名、電話、生日、性別及銀行資料共用；部門顯示名稱、頭像、官網介紹、備註、邀請網址、填單區 ID、可接服務及抽成資格各自保留。兩店 Logo 固定同尺寸，未隸屬的店家反灰。

員工端已移除「管理可接遊戲與服務」設定。HR 登入與工作台使用較深的主要按鈕底色及白字、明確的次要按鈕外框；停用狀態保留可讀灰字，不再透過低透明度淡化整顆按鈕。HR 專屬樣式也修正舊版全站 `.text-white` 規則造成的深底深字問題。

協作側邊欄已移除重複的「員工訊息」入口，員工通訊使用右下角的訊息按鈕。既有訊息頁連結仍可開啟。

手機與窄螢幕改用單一「功能選單」按鈕，點開後直式列出分類，再點分類展開細項；選取功能後自動收合。手機卡片、長文字、金額與下載項目可在容器內換行，橫向資料表在自己的區域內捲動。

協作資料、公告、人事申請和員工訊息在同一畫面讀取，保留來源。側邊欄僅有一個「訂單」分類，各種明細各列一次；點進明細頁後，同時顯示所屬部門的訂單區塊。活動位於協作選單，各店活動資格與回覆獨立。行政與福利表單內選擇申請部門；簽核表格標示來源，沿用各店的審核流程。

`lib/hrRoutes.mjs` 定義所有選單的實際路徑，含 `/personal/data`、`/order/order.details` 和 `/order/reward.details`。舊 `qiunai.wearestilllhere.com/staff` 以 308 永久轉至 `hr.wearestilllhere.com/collaboration/workspace`；舊網域首頁及其餘員工頁也轉至 HR 對應頁面，不再提供舊網域員工介面。API、主管路徑與合約簽署連結沿用原本路由。HR 的 `/staff` 保留為站內相容轉址。登入時保留合法的原目的頁。

## 金額與資料界線

合併提領依兩店可提領餘額比例分配，整數差額歸最後一個在職部門。分開輸入時，各部門可個別填額或填 0。不搬移歷史訂單、錢包、資格、報單頻道或簽核歸屬。合併銀行申請總額高於 1,000；分開申請時每個有申請的部門各高於 1,000。手續費依該部門既有規則計算，核准與匯款仍由各部門處理。

`hr_request_withdrawal_atomic` 在同一筆 PostgreSQL 交易內建立兩家申請或轉入本人的 ASD，並使用與既有 ASD 函式相同的部門鎖。批次識別碼防止重試重複入帳；瀏覽器角色不能直接執行這些函式。`hr_guard_salary_reservation` 也對舊入口的新申請序列化並檢查餘額，避免新舊入口同時超額預約。

共用個資與部門專屬設定使用不同的交易函式；共用儲存不修改暱稱、官網或頻道設定。秋奈 `allowed_services` 保留 JSONB 的服務名稱，深夜保留原本的 text[] 服務 key，不互相轉換。

## 部署

沿用既有私人 GHCR 容器及 Railway 服務；建置前確認 package 為 private，以固定 digest 部署。套用 `20261102000100_unified_hr.sql` 及 `20261102000200_hr_profile_services.sql`。在同一個 Supabase Auth 專案允許兩個新網域的登入回跳，保留其他既有入口。

主管網域由 `proxy.ts` 導向既有主管系統，根路徑使用原本 `/admin-login`，其他頁面、API 及資產保留路徑。主管應用程式本身不變。這個網域應掛在 HR 容器的同一個 Railway 服務。

深夜既有部署缺少協作及活動端點，因此 HR 容器保留原本按部門過濾的協作 handler 及深夜活動 handler；其他深夜 API 沿用既有服務。所有服務仍驗證登入及各自權限。現有安裝包仍可下載，舊秋奈員工入口跟隨上述轉址；這次不重包安裝檔。

## 驗證

`npm test`、TypeScript 與正式建置。`scripts/container-smoke.mjs` 檢查指定頁面、資產及未登入保護。`supabase/tests/hr_atomic_withdrawal.sql` 與 `hr_profile_isolation.sql` 使用獨立測試員工並完整回滾，不更動真實員工金額。銀行提領期間另以交易內的固定時鐘版本測試後回滾。

## 外觀主題

員工可在「資源 → 外觀主題」（`/resources/appearance`）切換秋奈或深夜外觀。秋奈使用既有小奈角色與延伸的雲端遊戲房插畫，包含雲朵、花草、遊戲機、耳機與貓咪；深夜使用官方金色 Logo 與午夜城市休息室插畫，包含暖燈、星空、月亮、植物與黑貓。背景、導覽、工作台橫幅、內容卡片、按鈕及登入頁一起套用。場景圖片使用 Next Image 依尺寸提供 WebP；文字卡片與表單使用不透明底色，裝飾禁止接收點擊。手機橫幅的圖片與文字分區。選擇記在目前瀏覽器，切換不會篩選部門或改變權限、個人資料與餘額。主管端維持原本介面。

## 主題商店與付款

「資源 → 外觀主題」保留免費的秋奈、深夜外觀，另有純白／純黑／純藍／純灰／純粉各 NT$10，長期販售、購買後永久使用。萬聖節限定版 NT$50，2026/11/30 23:59:59.999（台北時間）停止建立新購買，已購買的使用權不會到期。此功能提供付費後套用，沒有下載功能。

- 授權以 Discord 員工身分共用，兩店資料仍合併顯示。前端不信任 localStorage 的付費主題值，只有伺服器確認授權後才能套用；偏好存入 `hr_theme_preferences`。
- ASD 扣除 `users.coins`，留下 `wallet_logs`；扣薪先選在職部門，從已可用薪資扣款，同時記入該店扣項與已結算薪資錢包負數分錄。餘額不足不扣款、不建立授權。兩者的付款、帳務、授權均在同一個交易內完成，重送購買不重複扣款。
- 綠界使用現有正式金鑰與站內付 2.0 信用卡 SDK，並處理 3D 驗證。建立付款表單與前景返回都不解鎖；S2S 通知需解密、排除模擬付款，並向綠界查詢確認特店、訂單、金額、交易號與已付款狀態，再原子解鎖。失敗或未確認的付款不解鎖。已送出付款的訂單不提供再次扣款或任意取消；未送出者可取消。
- 已送出付款仍未取得結果時，10 分鐘後可手動向綠界查詢，並限制每筆每 10 分鐘最多一次。網路逾時保留確認中，避免重新扣款。
- 所有購買與授權資料表開啟 RLS，瀏覽器角色不能直接寫入或呼叫扣款、解鎖函式。伺服器依登入身分與即時員工資格授權，不接受客戶端指定買家或金額。
- `20261102000300_hr_theme_store.sql` 與 `20261102000400_hr_theme_payment_query.sql` 為新增 migration。`supabase/tests/hr_themes.sql` 的測試身分交易最後完整回滾；不使用真實員工餘額，也不對綠界送出實際扣款。

純色版不使用插畫背景。萬聖節版加入南瓜、幽靈、蝙蝠、蜘蛛網、糖果、魔藥與黑貓場景；文字卡片與表單維持不透明底色。第三方付款區使用亮色表單底色，圖片透過 Next Image 依裝置大小提供。

## 主題可讀性與品牌完整性

所有 HR 共用內容元件使用主題色票：協作指標、文件列表、表單、簽核狀態、附件、訊息視窗與登入頁都跟隨主題。秋奈延伸藍白雲朵遊戲房，深夜延伸午夜藍與暖金；文字區有不透明底色，裝飾不接收操作。

一般文字以 4.5:1、大字以 3:1 作為本次對比檢查門檻；另核對停用、輸入提示、選中與滑鼠停留的配色。移除跨主題切換時文字／背景顏色的淡入淡出，避免轉換途中變得不清楚。純白手機選單、純黑訊息氣泡、輔助說明、簽核狀態、登入次要按鈕與頁尾皆使用對應色票；訊息時間及文件註記最小 12px。檢查使用實際元件與範例狀態，不讀取或變更真實員工資料。

萬聖節的功能選單另有蜘蛛網、吊掛小蜘蛛與碎片貼紙；部分分類標題及選單格使用破角底板與裂紋。裝飾可輕微覆蓋字緣，但不接收點擊、不加入輔助工具朗讀；破碎造型只裁切裝飾底板，連結與分類按鈕保留完整點擊範圍。手機展開的直式選單亦保留這些細節，其他七套主題不受影響。
